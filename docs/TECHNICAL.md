# 技術仕様と検証

[README](../README.md) / [導入ガイド](GETTING_STARTED.md)

対象はWindows / OneComme 9.2.0-beta.0。他の版・OSは未検証です。固定loopback APIのGET /api/config・GET /api/servicesを読み、声・音量・エンジン・枠名のみを画面へ返します。元のconfigやURL、メタデータは返しません。コメントを外部へ送信しません。

通常音声は本体だけで管理します。変更したspeechフィールドのみPOST /api/config、変更した枠のoptionsのみPUT /api/services/:idへ保存します。現在のoptionsとマージし、接続・読み上げON/OFF・URLなどを変更しません。声や音量の指定が無効だった枠を標準設定へ切り替える場合、未編集の声・音量は変更前の有効値を保持します。

本体の基本音声は枠側の指定がない場合に使われます。表示は本体のエンジン選択とフォールバックに合わせ、標準エンジンの枠だけ編集できます。本体の0〜200%はそのまま表示・保持します。Web Speechの音量の実際の上限は再生側に依存します。

v2の永続データはsettingsVersion:2とjapaneseFrames:{枠ID:{voice,volume}}。voiceは実際の日本語音声名、@auto、@sameのいずれか。volumeはnullまたは0〜100の整数。nullは元の発話音量を維持します。通常の声・音量を複製して保存しません。削除済み枠の設定は別のIDへ転用しません。

日本語はかな・半角カナ・漢字で判定します。コメント全体を読むため、混在文の分割・翻訳・中国語識別は行いません。指定声が利用できない場合は、現在の日本語声→Sayaka→利用できる日本語声へ代替します。日本語声がない場合は元の声を維持します。元の発話音量0は上書きしません。

Electronのfile:かつ/out/renderer/に限定し、speechSynthesis.speakにラッパーを設定します。filterSpeechで付けた枠IDマーカーを再生直前に取り除きます。アプリ本体ファイルは変更しません。無効化時に復元します。外部エンジンへマーカーを付けません。内部処理に依存し、本体更新時の再検証が必要です。

旧版データを検知すると旧動作を継続します。移行プレビューの明示確認後に、対象枠の通常設定を本体へ保存し、日本語ルールを枠単位へ展開します。元の旧設定キーは削除せず残します。外部エンジンの枠・削除済み枠の旧ルールは保存先に残り、自動移行対象外です。

5秒ごとの再取得で未編集の表示を更新し、編集中の値は保持します。保存内容は変更項目だけ。本体の関連設定と日本語設定のハッシュで競合を検出し、書き込み直前にもoptionsを確認します。本体APIに原子的な条件付き更新機能がないため、最終確認と書き込み間のごく短い競合は防げません。保存処理は直列化します。途中失敗は保存済み枠を通知し、他の変更を巻き戻しません。

ローカルAPIはGETとPOSTを使用。旧PUTは設定画面を更新するよう通知します。通常のポート11180を前提とします。config全体は一時的にメモリへ読みますがログや診断へ出しません。権限はfilter.speech / services / configです。

## 検証

Node.js 22でnpm run check、npm test。追加のnpm依存は不要です。旧ルーティング互換性、本体表示・最小保存、200%、ミュート、日本語だけの上書き、競合、旧版の明示移行、部分失敗を模擬テストします。

画像生成兼ブラウザ検証はtools/guide-images/render.cjs（開発用Playwright・Edgeが必要）。架空データでデスクトップ・モバイル、保存、範囲、0%、自動更新とフォーカス、基本設定、移行確認を検証します。実際の本体APIからの読取と模擬書込検証を区別し、実際の聞こえ方は配信枠で確認してください。
